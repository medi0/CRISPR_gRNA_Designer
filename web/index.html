CRISPR guide designer

1. Genome

Load a genome to work on: your own FASTA file, or a synthetic one that comes with a planted bad guide.

CRISPR-Cas9 cuts DNA at a spot chosen by a short RNA called a guide. The guide is 20 letters long and must match the DNA right beside a three-letter signal called a PAM. For the common Cas9 the PAM reads NGG: any letter, then two Gs. A good guide matches one place and nowhere else. Cas9 forgives a few wrong letters, called mismatches, so a careless guide can also cut elsewhere. Those stray cuts are off-target effects. This program finds every candidate guide on both strands, searches the whole genome for near-copies, and ranks guides by how unique they are.

Demo in under a minute. Press the 300 kb button below. That genome hides one guide at position 100,000 and 12 near-copies of it. Open page 3, press Rank guides, and the planted guide shows up in the worst table. Click its row to see all 13 places it matches. Page 4 then shows how much faster the index is than checking every position.
How it works

Reading a FASTA file takes one pass, O(n) for n letters. Only the first record is used, letters are upper-cased, and anything that is not A, C, G or T (N, line breaks) is dropped. The synthetic genome is built in one pass too: AT-rich background, CpG pairs mostly removed as in real genomes, three CpG islands, and the planted guide with its decoys.

2. Find targets

List every spot where a 20-letter guide could sit next to an NGG signal, using three different string-search methods that must agree.

How it works

The only fixed part of a target is the PAM's two Gs. So each method searches for "GG" on the forward strand and "CC" on the reverse strand (the reverse strand reads CCN). The position gives the other 21 letters for free.

KMP builds a table so the text pointer never backs up: O(n + m). Boyer-Moore compares the pattern right to left and jumps ahead over text it can rule out: best case O(n/m), worst case O(n times m). Rabin-Karp slides a rolling hash and checks only hash hits: O(n + m) expected. With a 2-letter pattern none of them can show its strengths, so the second table repeats the test with a 16-letter pattern.

3. Design guides

Score every candidate guide in a region and show the safest and the riskiest.

How it works

Each guide is searched against the whole genome for sites within k mismatches. Every near-copy adds risk, and a mismatch close to the PAM adds less risk than one far from it, because Cas9 tolerates far-end errors (published MIT weights). Specificity = 100 / (1 + total risk), so 100 means no near-copies anywhere. A GC content outside 40 to 70% costs 20 points. Guides containing TTTT are dropped.

The best K are kept with a size-K min-heap, O(N log K) for N candidates, then sorted with quicksort, O(N log N) on average. The median specificity comes from median of medians, O(N) even in the worst case. Region limit: 30,000 bases.

4. Off-target speed

Compare checking every genome position with looking guides up in a seed index.

How it works

Brute force slides the guide over every position on both strands and counts mismatches: O(n times 20) per guide. The seed index uses the pigeonhole principle. Cut the 20 letters into k+1 pieces. A site with at most k mismatches must match at least one piece exactly, because k errors cannot touch k+1 pieces. So every PAM-adjacent site is hashed once per piece, and a query only reads the buckets for its own pieces. Candidates are checked with one XOR and a bit count on a 2-bits-per-letter code. A site found through several pieces is reported once, from its first exact piece, with no hash set.

Building the index costs O(sites times (k+1)) once. After that a query touches only its buckets.

5. CpG islands

Mark the stretches where C and G are unusually common, a sign of regulatory DNA.

A CpG island is a stretch of at least 200 letters that is rich in C and G and has more "CG" pairs than chance would give. Real genomes lose most CG pairs over time, so islands stand out. They often sit at the start of active genes.

How it works

Prefix sums of C, G and CG counts make every 200-letter window two subtractions per count, so the scan is O(n). A window counts when GC is above 50% and observed/expected CpG is above 0.6, where expected = (C count times G count) / 200. Touching windows are merged into one island.

6. Alignment

Line up two sequences letter by letter and score the best fit, with a memory-hungry method and a frugal one.

How it works

Scoring: match +2, mismatch -1, gap -2. Needleman-Wunsch fills a full table of m by n scores and walks back from the corner: O(mn) time and O(mn) space. Hirschberg gets the same optimal score in O(n) space. It runs the table fill keeping one row, forward over the first half of the first sequence and backward over the second half, finds where the two scores add up best, splits there and recurses. Time stays O(mn). Smith-Waterman finds the best matching stretch inside both sequences (local alignment) and is shown as a score only.

7. Genome vault

Compress a genome, lock it, open it again, then break a toy version of the lock.

Teaching implementation: a 64-bit RSA modulus and a simple keystream cipher. Do not store real data with it.

How it works

Huffman coding gives common letters short bit codes: O(n + s log s) for n bytes and s distinct symbols. A random 32-bit session seed drives a keystream that is XORed over the data, and RSA locks the seed: modular exponentiation takes O(log e) multiplications, and the key pair comes from Miller-Rabin primality tests and extended Euclid. A checksum (FNV-1a) detects a wrong key or damage.

Pollard's rho attacks RSA by factoring the modulus. It needs about the square root of the smaller prime in steps, so 2^(b/2) steps for a b-bit prime. Each extra 2 bits of prime multiplies the work by 2. Real keys are far beyond what this program can run, so the chart below shows measured growth and an extrapolation, not a break.

8. Benchmarks

Time the main algorithms on genomes of growing size and put the curves next to the theory.

How it works

Each size gets a fresh synthetic genome. Dashed lines show the theoretical growth anchored at the first measurement: straight scans should grow like n, alignment time and the full table like n squared, Hirschberg memory like n. Both axes are logarithmic, so a power law is a straight line and its slope is the exponent. This takes a few seconds.
